## Wall geometry, rendering and collision

`WLStream2Spec`, CODE6:aee4–af96, reads an axis byte, discards the next byte, then reads five signed16-bit words: fixed coordinate, start cell, start inset, end cell, end inset. Axis1 is vertical (fixed column); axis0 is horizontal (fixed row). `WLSpec2Globals`, ad5a–aec4, iterates the **inclusive integer range** `3*start+startInset .. 3*end-endInset`. Do not interpret the insets as pixels or simply draw a thin line between fractional grid endpoints.

For each integer q, cell=floor(q/3), part=q%3. At part0, source enables a short vertical or horizontal joint tile. At part1, it ORs cross-mask8 vertically or4 horizontally; at part2, it ORs mask2 vertically or1 horizontally. Crossing and repeated specs union their masks. `WLDrawBackground`, b7b0–b8b8, and `WLCreateSprites`, b568–b79e, scan the88 cells in row-major order, producing vertical joint frame0, horizontal joint frame1, then cross frame4+mask. Resource222 yields51 tiles using11 distinct frames. Wall count12 is therefore not the sprite/collision count.

`WLFetchBG`, a916–a950, selects graphicgroup800. The private profile retains all24 frame descriptors and original collision scanlines. Active tiles use frames0/1 and5–19; frames2/3/4 are cleared/shattered background forms, and20–23 serve segment collision decomposition during shattering. Neither shatter nor bomb interactions is required by Walls, which has no relevant records. They are not implemented by the bounded helper.

`WLCreateSprites:b5a8–b5b4` passes DATA Point(+6,+6), at A5−0x42c, to ROGetPixel. `WLDrawBackground` uses the same location. With logical grid=B+(12,11), **tile image/collision top-left is logical cell + descriptor(x,y)−(6,5)**. This differs from both WA−(44,43) and SP−(8,7). Use48-pixel cell pitch. Private offsets retain descriptor orientation and exclusive bottom. Source collision uses the original outline, not SVG alpha, shadow geometry or a generic line thickness. Group800 outline indices−1 are genuinely noncollidable; ordinary tile frames have valid outlines.

`WLCheckCollisions`, ba82–bac4, scans active entries and returns the first matching source outline. No difficulty/activation mask is stored in WL specs. Walls start present; WLReset:aace–ab54 restores current flags from initial flags. Do not infer conditional hiding from the discarded padding byte. Bomb/shatter paths elsewhere can remove current tiles; those mechanics remain outside this level qualification.

## Actor response and callback order

`WACheckWalls`, d00e–d056, first checks **WAInfo+0x6a**, the saved WASpec+0x14 byte (`WAInfo` embeds the22-byte spec at+0x56). This is the version12 first byte exposed by the decoder, not the actor activation mask or color. In Walls, both human records and the lower green actor enable it; the three right-side enemy variants disable it. Difficulty visibility still independently uses the actor activation mask. The second human remains hidden in single-player.

An enabled contact calls `WABounce`, cf50–cf8e, which calls `WAReverse`, c5be–c63c. It negates the sprite direction; if sliding it also negates slide progress direction and both displacement components. It marks action state changed and clears human pending/latch state. Sound4 applies to humans and30 to enemies in the normal nondemo branch. There is **no immediate wall-contact death call** and no position separation, penetration correction or extra reverse-step in these routines.

There is a crucial exception: `WAHeroOneFrame:d4c6–d4e8` increments a counter for consecutive wall/door collision callbacks, resets it when collision is false, and calls `RODied(hero,36)` after the counter exceeds3. Thus the fourth consecutive collision is lethal. This is an anti-trapping guard, not a life counter or damage score. Enemy one-frame processing has no corresponding guard. The tutorial's general nonlethal description must not erase this source exception.

Hero order (`d498–d54e`) is collision tests on the **current pose**, guard update, stop-sliding processing, input/action processing, start-sliding processing, won/dead test, then animation/frame selection. The wall bounce affects that subsequent animation step. Other hero hazard callbacks precede wall checks inside `WACollide:d07a–d146`; wall checks can be skipped when an earlier supplied collision flag already applies, and doors are tried only when no wall bounce occurred. Do not move wall checks after the human frame advance merely to share the enemy loop.

Enemy order (`d938–d9c0`) is animation/frame selection, collision tests (including enabled wall checks), stop-sliding, program action, then start-sliding. Both use the existing scalable WA clock/subdivision; walls themselves have no animation clock. The previous timer review remains applicable. Runtime callbacks, death/reset, mode-dependent sounds and input-latch clearing stay coordinator-owned.

## WP reference and instruction contract

`WPFindPrograms:f10c–f178` requires signed reference>=0 and <loaded program count. It otherwise clears the program pointer and sets action index1. All six Walls references are−1: none of the three serialized programs executes. `WACreate:e174–e1fa` has a separate PROG-resource fallback only when the stored-WP loading flag is not set; `WPCreate:f190` sets that flag. Do not reinterpret−1 as the last WP, default to program0, or attach stored strings by actor order.

For future integration only, `WAControlFromPC:caba–cb80` consumes one Pascal-string byte at the actor's current index, increments it, and in ordinary looping mode wraps to1 when beyond the stored length. It sets grab for `s` or `f`, reverse for `b` or `f`; other bytes pass both false. Thus `n` means no action bits. `WADirectEnemy:cbac–cbda` calls this only at frames divisible by16 and when not sliding. This is one instruction per eligible source callback, not every display frame or elapsed tick. Grab/reverse flags are inputs to the existing `WAAction:c65e`; they are not unconditional teleport or direction mutations. Dot programs use additional paths and are explicitly outside these helpers.

## Acceptance limits and generation constraints

The ten tests cover inclusive endpoint/inset behavior, cross merging/deduplication, tiny joints, malformed bounds, independent wall permission, fourth-contact death/reset, signed program references, action flags, eligible instruction consumption and loop wrap. They contain synthetic data only. They prove helper contracts, not level solvability or runtime parity.

A generator using these mechanics must constrain each axis/fixed coordinate and inclusive interval to the88-cell source grid, respect the18-spec limit, union overlapping tiles, preserve the tiny joints/short arms, retain actor wall permission and activation masks independently, and count only referenced executable programs. A complete path solver also needs action eligibility, source outline collision and safe intermediate rotations; graph connectivity of present dots alone is insufficient. No generated level or solvability claim is delivered.

Native Walls frame/anchor matching, current difficulty visibility, human bounce and fourth-contact behavior, bottom-enemy wall response, distinct source callback ordering, text, sound and a reachable goal remain outstanding. The supplied source art/profile must be checked against a Walls native frame before acceptance.
