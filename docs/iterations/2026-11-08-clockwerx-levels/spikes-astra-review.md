## Source behavior and integration contract

- SP serialized words +0/+2 are grid row/column. Words +4/+6 independently select vertical/horizontal subcell offsets from `[0,6,24,42]`, initialized by `CODE6:983c–9852` and applied at `986e–988e`. They are not orientation, length or speed. The final four bytes are the activation mask (`998a–9a0a`, `9a90–9a9a`). This level uses offset indices 0 and 2, yielding 0/24-pixel offsets. Preserve duplicate grid positions: distinct offsets are distinct spikes. The 48-pixel pitch and grid origin (74,72) agree with the supplied 640×480 native scene after dividing its 2× capture coordinates by two.
- `SPInit` loads graphics group **200** (`96dc`). It contains four 18×18 frames with separate four outlines. `SPSpec2Info` sets frame range 0–3, initial frame `spikeIndex % 4` (`9910–991c`; compiler signed remainder is `CODE1:058c`), direction +1, and one of four shared timer pointers by `spikeIndex & 3`. `SPPeriodicProc` computes `floor((SPtimer + phase)/4)` (`9c74–9c98`). This is an animation clock, not a retract/extend or damage period: every visible spike is checked continuously. The timer creation argument is 200 (`9748`); its conversion to seconds is not qualified here. Do not replace it with a guessed 60 Hz animation.
- `SPCheckCollisions` checks visible spikes and calls `SUCheckCollision` (`9c06–9c44`). A collision returns an SP index; −1 means none. `SPKillsHero` is simply index != −1 (`9bdc–9bf0`). `WACheckSpikes` passes death reason **8** to the existing hero failure path (`cd72–cda6`). Hero-only dispatch is proved in `WACollide: d092–d0ee`; enemy-frame dispatch sets that flag false (`d964–d972`). Thus spikes do not injure these enemy hands. No intermittent immunity phase was found for SP itself.
- `SUCheckCollision`, `CODE4:41d6–4450`, first rejects disjoint bounds. Missing outline-store pointers mean no collision. When both loaded outlines are rectangle-only, overlapping bounds collide. Otherwise it compares **one inclusive left/right span per row**, skips rows whose left endpoint is −1, handles vertical reflection and loops up to the exclusive bottom row. These are original collision outlines, not the transparency mask or enhanced SVG perimeter. Gaps within a row are filled by this span representation. The generic `outlineCollision` helper follows this algorithm; callers must supply integer original world bounds, source frame and flip flag.
- WA type→source group mapping: **0→700**, **6→4300**, **2→4400**, **3→4500** (`be0c–bf28`, `daf4–dbc2`). The existing private baseline already includes all four distinct SVG variants. Green and blue have different source images and silhouettes; they must not be recolored aliases. Their relevant source groups each have 64 frame descriptors backed by 33 images; vertical reflection shares the remaining images.
- All four WA records have program reference **−1**. `WPFindPrograms: f11c–f164` clears the program pointer and resets the instruction index to 1 for a negative reference. Accordingly the level's two embedded WP programs are unused under normal loading. Do not assign them by array order. The first two actor slots use the hero callback in ordinary play (`dc6e–dc86`); slot 1 is hidden and its clock pointer cleared in single-player (`dcea–dd14`). Type 6 is the second human/black hand, not an enemy or keyboard demo. Slots 2/3 use enemy callbacks. `WADirectEnemy` only executes a program at frames divisible by 16 (`cbac–cbd4`); with null program and no demonstration mode, nothing happens (`cacc–cad0`, `cb4a`). These enemies rotate at their initial pivots.
- WA initial frame is twice the serialized half-index, then masked to 0–63 (`dcb0–dcbe`, `c248–c26c`). The serialized signed word +8 becomes direction; this level's green is +1 and blue −1 (`dcc2–dcca`). Both use speed class word +14 = 1; the hero uses class 0 (`dc08–dc2a`). Initial DATA tables supply multiplier 1 and normal divisor 2 for both classes, with slowdown divisor 4 for class 1 versus 2 for class 0. `WALatchTimer: e6fa–e78e` accumulates elapsed common timer units and advances by multiplier/divisor, subject to a catch-up cap. Absolute wall/guest time conversion remains unqualified; reuse the already-qualified engine clock only after coordinator comparison.
- Hero/enemy collisions call the same source outline function. When pivots differ, outline contact proceeds to `WAHitEnemy`. At the same pivot, source additionally requires frame separation ≤4 or ≥60 of 64 (`e64a–e67e`). `enemyFrameGate` exposes that rule. There is an additional dot-state protection branch (`e5a2–e5d2`); do not equate every hero/enemy outline intersection with unconditional death until that dot-state condition is integrated. No score rules were added here.

## Generation constraints and remaining work

Use the source grid and subcell lattice; never merge spike records by dot coordinate. Test candidate human rotation and every transfer interval against source outlines, including the swing/reverse trajectory and the complete spike animation cycle. A geometrically close handover is not automatically safe. Preserve enemy starting phase, signed direction and speed class; solve against their evolving phases rather than static hand segments. Normal Spikes enemies have fixed pivots because their program references are absent. Generated programs require separately qualified action timing and opcode semantics.

For safe generation, require reachable bonus/goal states, legal pivot transfers, a safe spawn interval and a path through timed hazards. The source's same-pivot angular gate and dot-state protection must participate in that simulation. This pass supplies collision primitives, not a solver or proof of solvability. Death reason dispatch, life loss, post-death delay, restart reset details, goal completion ordering and physical controller qualification remain outside this bounded source pass. Do not advertise Spikes as qualified until native gameplay, collision, restart and completion checks pass.
