# Oil integration source supplement

This source-only supplement resolves the static-dot, clipping and traversal adapters for catalog Oil (ordinal 5, resource 224). It adds no runtime activation or native qualification. Root owns those checks. The separate private group300 profile does not modify the existing 50-payload Oil candidate.

## Static dot state and source frames

Use the serialized source slot `index = row * 11 + column`, retaining all 88 positions, including absent slots. Raw dot pixel is `logicalCenter - (16,15)`: DOGetInitialPixel (CODE6:2a80) calls ROGetPixel with DATA point(-4,-4), while logical dot centers are raw RO grid plus(12,11). DOGetCurPixel (2b60–2ba6) reads the retained sprite location when a main sprite exists, otherwise DOInfo+8. An optimized/background dot still has that main sprite. Do not substitute its visual center for the raw base.

For version12, first serialized word bit0 determines presence. Bit1 is bonus, bit2 goal. Bit0x4000 is a separate initial-state flag, not a color permission bit. Second word low four bits are activation mask; all upper twelve bits are color attributes. DOCreateAll at CODE6:393c–3b80 reads both words. A missing activation bit suppresses the source's selected optional features, including bonus and goal, but retains presence. Oil's 50 present cells all have secondary word15, so every present cell is active at Child and has color attributes zero. No unsupported special-dot flag appears in this resource.

DOCreate (3752–38c0) selects color bits using difficulty index d and secondary-word masks: red=`0x10 << d`, green=`0x100 << d`, blue=`0x1000 << d`, for d=0..3. DOGetColorOffset (2c08–2c38) converts the runtime red/green/blue bits into `colorOffset = red + 2*green + 4*blue`. Colors in that order are silver, red, green, red/green, blue, red/blue, green/blue and red/green/blue. Color determines appearance and other actor rules elsewhere; it does not make a static Oil dot unavailable to DOCanGrab.

In the color-look path, group300 frame=`1+colorOffset` for an uncollected bonus and `9+colorOffset` for an ordinary or collected dot. CODE6:2d96–2e28 implements these choices; DOInit's look-mode flag is selected by the enabled 8-bit color path at CODE7:43d0–43e2. For Oil, the main collider frames are therefore1 and9. Both have raw descriptor bounds left11/top11/right21/bottom21, but they reference different original outlines (1 and0 respectively). Do not replace them with one generic circle or infer the collision from the SVG.

The alternate monochrome-look path uses bonus frame100/101/102/103 for no channel/red/green/blue respectively, with red then green then blue precedence; ordinary frames9/104/105/106 use the same precedence. That is a fallback branch, not the current color candidate. Frame107 represents unavailable main-dot appearance; it is not selected for Oil's ordinary present dots. Full group metadata remains private to preserve direct frame indexing; unreviewed special frames are not qualified by extraction.

Goal decoration is a separate group300 misc sprite at frames17..22 (DOGetLookMisc 2e58–2e8a, DOCreateMisc 3118–327e). Its base is the same raw dot pixel. All six goal decoration frames lack collision outlines. DOCheckCollisions scans the primary DOInfo array, not the misc array; the goal's underlying main dot uses frame9 in Oil. Goal decoration and attention flourishes must not enter the DP dot-contact loop.

DOSpec2Info (3484–36b0) initializes nonhuman permission DOInfo+0x10 and human permission+0x11 from the saved presence byte DOSpec+4, copied to DOInfo+0x18. Thus Oil's 50 present static dots grant both permissions, including bonus, collected and goal dots. They remain granted on ordinary pickup; special disappearing/moving/up-down mechanisms can later change human permission, but are outside Oil's supported subset. Never derive these permission bytes from secondary color bits.

DOOptimize (3cca–3dae) backgroundizes a present human-grabbable main dot if `(runtimeFlags & 0x0b94) == 0`. Ordinary and goal main dots qualify; bonus main dots do not, because runtime bonus is0x800. Backgroundization keeps the main sprite and frame, hides it, moves it from layer4 to layer6, saves its raw pixel, and sets DOInfo+0x12=true. In Oil this gives 41 background main dots and 9 initially visible bonus main dots. Goal decoration remains separate. A collected bonus clears0x800, calls DOLook2Frames to switch1→9, and stays visible with+0x12=false; it is not re-optimized at pickup (DOUnbonus 4944–49e2). Reset restores each initial bonus/frame.

## The two dot lookup adapters

`DOFindGrabbable` (CODE6:4260–436a) is position acquisition, not an outline test. The PU call supplies a target raw pixel, GridPos(0,0), false and true. The routine adds48×GridPos to that target and scans source slots0..87. It requires saved presence+0x18. With the final argument true it obtains the current raw pixel. Its inclusive box compares both coordinates to target±6; the source branches reject values below the lower or above the upper bound. It returns the first match. This path ignores main-sprite visibility and the background flag.

`DOCanGrab(false,...)` then reads the first found dot's nonhuman permission+0x10; `true` reads human permission+0x11 (4464–44fe). A denied first match returns false immediately; it does not continue searching for a later overlapping permitted dot. DPGrabbed's index overload (4394–443a) obtains that dot's current raw pixel and calls the same lookup with GridPos(0,0), current-position selection and human=true. All static Oil present slots grant both permissions, but keep lookup and permission as separate steps in a reusable adapter.

`DOCheckCollisions` (4d0a–4d56) scans exactly88 main slots in ascending index. Eligibility is `mainSprite != null && (backgroundFlag12 || mainSprite.visible37)`. It passes the main sprite's CURRENT source frame and the DP sprite to SUCheckCollision and returns the first overlap. It does not check human/nonhuman permission. Only after this lookup does DPFrameProc discard a result equal to previousDot; filtering previousDot inside the adapter would wrongly allow a later overlap. Use the original RAW bounds and scanline outline, translated by each sprite's raw base, and preserve no-outline versus rectangle-outline distinction.

For static Oil the bounded adapter can therefore retain one record per source slot: presence; raw pixel; initial bonus; collected state; main-frame1 or9; backgroundized flag; sprite visibility; both permission bytes. Absent slots have no collider. A goal adds a separate visual decoration. This represents source state without publishing the original map.

## Universe bounds and coordinate conversion

The normal playfield is584×424. GP initialization in CODE1:5900–595e builds and centers that frame, then SUCreateUniv (CODE4:4568–46b4) creates its background/backbuffer and screen information. SUSetupScreen (0008–01bc), called at4638–463c with `universe+0x70`, intersects the destination with the screen and translates its bounds by minus the destination origin. Thus the full unobscured source-local universe bounds at+0x84 and default clip at+0x8c are `{left:0,top:0,right:584,bottom:424}`. SUSetupScreen writes the normalized bounds at0174–0196; screen-frame origin remains at universe+0x94.

The port's canonical board coordinates include frame origin(28,28). In that coordinate system the equivalent full DP clipping bounds are `{left:28,top:28,right:612,bottom:452}`. Keep raw sprite bases and bounds in the SAME coordinate space. Do not use the logical dot grid extent, and do not subtract the grid's centered origin. Both display sizes use the same full playfield bounds.

DPFrameProc (CODE7:09b0–0a14) reads the CURRENT clipped universe rectangle at+0x8c/+0x90 and compares the sprite BASE, not descriptor extents: hide/detach when base is `< left`, `> right`, `< top` or `> bottom`. Equality remains inside. It performs this check only on the active dot-collision phases, after any contact repositioning. SUSetClip/SUClipUniv (CODE4:475c–47f6) can reduce the rectangle for a window/screen clip; SUUnClip restores original normalized bounds (4812–482c). The numeric full-frame bounds above are the normal full-board adapter, not a claim that every obscured or differently sized native window has those clip values.

## Sprite and actor callback order

ROGetLayer maps logical layer IDs to shared physical lists (CODE7:4652–46e8). ROStart appends those physical layers in this processing order (4ea2–4f0a): 5, 4/7, 8/9, 3, 10/15, **11 (PU/DP/faders)**, 2, **1 (enemy hands)**, **0 (human hands)**, 12, 13/14/16. Logical aliases denote the same physical list. SUAddLayer appends each layer to the universe tail (CODE4:4872–48aa). SUProcessUniv iterates that order, skipping a layer with its processing-stop byte+0x10 set.

WASpec2Info chooses layer0 for actor slot indices0/1 and layer1 for indices greater than1 (CODE6:dbe0–dbee). The field compared is actor index, not WA raw type. Oil's two serialized human slots have raw types **[0,6]**, correcting the earlier report's mistaken “both6”. Single-player hides/stops slot1. Oil has no ordinary enemy hand. A normal source sweep runs Oil before the human collision/input/movement callback; source order is not hero movement followed by Oil. Existing engine approximations remain root's integration boundary.

PUCreate (CODE6:8554–8568), DPCreate (CODE7:0c42–0c58) and DPActivateFader (0604–0618) pass priority0 to SUAddSprite on layer11. SUAddSprite (CODE4:2594–2644) appends priority0 to the tail; nonzero priorities use a separate sorted insertion path. Existing PU sprites are appended in filtered record creation order. New DP and faders append at creation time.

SUProcessUniv caches `next = current->next` at CODE4:4a82 BEFORE invoking SUProcessSprite at4a88. After the callback it resumes that cached successor at4a8e. Consequently, an append made by the current tail is not traversed in that sweep; an append made when an older successor exists can be reached when traversal later visits the old tail and reads its now-updated next pointer. Do not use an unconditional “process every appended sprite immediately” rule.

Regardless of whether the newly appended sprite is reached, PU→DP, clones and faders snapshot the current MT client count on creation. SUIsFrameTime (3e6c–3e9a) compares that snapshot to the live count, updates it only on a difference, and only then lets SUProcessSprite invoke a callback. Hence there is **no new DP frame callback on the same client count**. A later count change, even while still within a broad host iteration, is a different source-clock case. Persistent clocks and traversal sampling remain necessary; do not replace this with elapsed-count catch-up.

DPCreate calls DPGrabbed synchronously after insertion. DPCalcDir calls DPClone synchronously before the parent's base/frame/dot mutation. DPClone creates the child (including its initial DPGrabbed), applies opposite axis preference, calculates its direction and sets moveDeadline=1; only then does the parent reset its clone deadline, leave its old dot and advance its first travel frame. Delay-to-first-child-frame still follows the client-count snapshot above.

## Human grab death, synchronous helper hook and checks

DOGrabbed calls DPWandGrabbed first (CODE6:4612–461a), before goal/bonus effects. After the special-dot prelude, it calls `RODidDie(hero)` at471e–4724. If true,472a branches directly to function exit47ee. Thus a reason10 death from DPWandGrabbed suppresses goal completion and bonus pickup on that grab. Goal handling begins472e and bonus handling477c. RODidDie is CODE7:5274–5286, reading the per-human death latch set by RODied. DOInitialGrabbed (CODE6:458a–45e0) temporarily clears the bonus flag and calls DOGrabbed, then restores the flag, preserving initial bonus while still notifying the DP pivot hook.

`advanceDroplet` now accepts optional `onClone(event,parentSnapshot)`. It calls the hook after choosing direction and before parent clone-deadline reset, base reposition, frame update or current-dot clearing, matching the source synchronous boundary. Root should allocate the child, execute its initial arrival/death/permission effects, compute its opposite-preference direction and set moveDeadline=1 inside this hook, snapshotting the current DP clock. The returned clone event remains a diagnostic record; **do not dispatch it a second time**. Without the hook, returned events alone remain sufficient only for pure state inspection, not exact synchronous integration.

The new test asserts the hook sees the parent's old dot/frame/base/deadlines plus selected direction, verifies callback snapshots cannot mutate reducer state or diagnostics, then confirms later dot-collision work observes the hook's side effects. All12 Oil helper tests pass. No runtime tests, native runs, browser runs, builds or benchmarks occurred in this supplement.
