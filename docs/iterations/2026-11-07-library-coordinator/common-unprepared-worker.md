# Common first-pass requirements for an unprepared title

Read the individual assignment first. Work only on that title in the existing dev checkout. Read AGENTS.md, modernization skill/tuning reference, next-session handoff and per-game worker brief. For structured native behavior, also read systemless-headless and its play guide. No nested delegation, commits, push, deployment or uploads. A fresh worker is selected as gpt-6.1-sol for each game; report tool selection without pretending to independently verify model identity.

Preserve original SheepShaver media, both forks, Finder metadata and existing preferences. Originals are read-only, never mounted or run writable. Check source hashes around extraction. Keep private images, assets, preferences, registration values, disassembly, scenarios and screenshots under the assigned D: scratch directory, outside Git. Existing three-game IDs, mappings, executables and depth remain unchanged. Do not reset/import/replace browser state. Root controls browser save export and captures.

Inspect exact executable architecture, version evidence, sibling resources, SIZE partition, display requirements, preferences and controls. Unknown fields are discovery tasks, not permission to guess. Record versions separately; do not replace a configured newer copy with an older supplementary/Trash copy. Alias/registration/editor applications are not the game executable. Record uncertain helper/content dependencies rather than omitting them.

Always do a narrow read-only Boot/System Folder/Preferences metadata check by title/name and executable Finder creator, even if the title folder/readme does not mention preferences. Do not dump values. If an existing preference is found, preserve its forks/Finder fields in a separate copied fixture and verify it is actually reachable via the native virtual preferences path; merely placing a copy somewhere is not proof it was loaded. A log saying a missing preference was newly created identifies a fresh/default-state test. Label that state and resolve or explicitly retain the mapping gap before recommending per-title settings. Keep source/Boot hashes and previous diagnostic fixtures intact.

Use existing read-only extraction helpers or prepare the smallest explicit copied fixture. Cache environment is D:/SystemlessBuild/uv-cache; machfs1.3/macresources are already available in the environment executable recorded by the assignment. Existing scripts/hfsplus_read.py supports inline extents only and must refuse overflow rather than return partial forks. Reopen generated images and compare every selected fork/type/creator; preserve flags/dates where represented. Do not silently truncate names or drop a fork. Any reusable helper must pass focused synthetic preservation/path-guard checks before use. Do not indiscriminately copy unrelated root applications as dependencies.

Reuse D:/SystemlessBuild/target/ci-test/systemless.exe for bounded native behavior where appropriate; it reports0.110.1 but exact compile revision is not established. Native frontend ticks and this diagnostic build are not release-browser performance. Explicitly choose68K for a fat title's initial68K test, or PPC when the inspected executable requires it. Use exact SYSTEMLESS_LOAD_EXECUTABLE. A startup may need finite readiness/menu actions; inspect images before selecting coordinates and before claiming behavior. Never guess expected pixels. Record explicit exploratory display settings and partition rather than presenting them as verified requirements.

Seek a representative initial gameplay scene and a bounded useful input/menu/pause check. A successful action script or launch screenshot is not a compatibility certificate. Report motion/timing, busy scene, controls, pause/menu, sound, saves and physical controller separately as observed/pass/fail/untested. Non-silent samples are not audible fidelity. Without independent reference, no pace/collision/scoring fidelity certification. If there is a substantial compatibility obstacle, preserve the smallest reproduction, exact failure, likely missing service and low/likely/high next-step estimate when grounded; stop that investigation branch and return so the queue proceeds. Do not sprawl into shared runtime fixes or patch original executable bytes.

Extraction follow-up: the helper now prevents machfs's automatic alias regeneration by clearing only its derived Python alias-target reference on copies, while preserving original raw file forks/Finder fields. Raw aliases may still point to their old volume; do not claim they resolve. Original folder Finder information remains unexposed by machfs; represented folder dates are retained. Include these limits in copied-fixture qualification.

Readiness checks should use the documented input: a mouse-controlled game may require actual playfield movement/button input beyond selecting New Game. If documentation permits up to256colors,8-bit is a defensible exploratory probe; a4-bit failure alone does not establish generic incompatibility. Record pre-button and post-button states separately when comparing depths, and do not call unexpected imagery a proven renderer defect without reference evidence.

A short blank capture is not automatically a startup blocker: 3-D Cannon showed its title only at a later tick332 observation. If a window has appeared without an error/halt, one finite later startup observation can distinguish progress before concluding readiness is unresolved. Do not endlessly raise budgets or extend a real halt/assertion/timeout failure without evidence of progress. Keep original SIZE unless a separately evidenced memory experiment is explicitly coordinated.

Bound wall time as well as simulated ticks. A guest call may prevent the scenario from reaching its next tick/capture. If a probe has no meaningful progress at a reasonable recorded wall bound (the Adventure follow-up used about90seconds), stop only the exact process/session you created, preserve its partial evidence, and release workload. A self-aborted run is not a completed scenario or proof of a particular missing service; record final counters as unavailable if no final report exists. Never stop unrelated user processes.

No visible IAB in subagents: that surface is root-only. Do not attempt browser/Windows Computer Use or alternative raw CDP/Playwright/shell UI automation. Root has successfully used supported IAB in the resumed user turn. After native/extraction workload completes, message the coordinator with readiness/controls and explicitly release workload ownership; then only lightweight documentation may continue. Root can measure a prepared release entry; absent compiled entry is preparation work, not a game compatibility failure. No expensive release build for documents or an uncoordinated batch addition.

One native emulator, extraction/asset conversion, heavy build or performance capture at a time. You own that workload exclusively until release; coordinator performs lightweight review only. No broad process termination to improve measurements. Keep scratch/builds on D:, which had about481 GB free on2026-11-07; rediscover if doing a large operation.

Return a concise summary only after evidence is durable.
