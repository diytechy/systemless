No browser, emulator, native run, build, benchmark, media/save change, commit or upload was performed in this pass.

The normalized version12 resource has an11×8 display, serialized stride11,90 raw round-time units,50 present dots,9 bonus flags,1 goal and no inline dot programs. Counts are SP1, PU3, WP5, WA2 and TX9; all other object sections are empty. The two serialized human slots have raw WA types [0,6], with negative program references (corrected from the original report's mistaken “both6”). ## Lifecycle and collision

PU is a dormant puddle that creates a separate DP pursuing droplet. It is not an immediate hand-collision death hazard. PUStream2Spec (CODE6:83c8–8438) reads row, column, kind and, for versions greater than7, a32-bit activation mask; older source streams default that mask to15. The helper intentionally accepts only the five-word newer layout. PUCreate (84a6–857c) filters the activation mask before counting its11-slot capacity.

PUSpec2Info (8050–8112) resets triggered=false, deadline=0, targetDot=−1, visible=true and detaches the animation clock. Initial frames by kind0..3 are [4,0,1,2]. In logical-grid coordinates, raw PU sprite offsets are [(-25,-15),(23,-15),(-4,10),(21,12)]. The acquisition target uses grid offsets [(0,0),(1,0),(0,1),(1,1)], followed by the raw dot offset(−16,−15). These are distinct from visual dot centers. Add RAW source descriptors once. Large logical origin(74,72) applies to this resource; small origin(98,96) is supported by the helper's origin argument.

WACheckPuddles (CODE6:ce28–ce42) runs PUCheckCollisions then PUActivate. PUCheckCollisions (85ea–862e) scans instantiated order, ignores already triggered puddles, and returns the first original-outline overlap. Only four PU frames have outlines: the dormant frames0,1,2,4. Human current-pose hazard checks put puddles after spikes/goodies and before matches/sparks/bullets, walls, doors and switches. Ordinary enemies invoke this puddle path only in the source demo branch; Oil has no active enemy hand. Human input/action and animation occur later in the existing human collision sequence.

PUTrigger (8138–81a0) requests sound29, attaches scalable100 at its current count, selects range4..7 for kind0 or0..3 for other kinds, and sets deadline to a fresh TickCount()+MTAdjustPeriod(150). It retains its current frame. Each PUFrameProc (82a0–83a4) first advances exactly one frame, then tests the unsigned strict condition latchedTick > deadline. When expired, it calls DOCanGrab(false,targetPixel,GridPos(0,0),false,true). No eligible dot means the waking animation continues and lookup retries on each later callback. DOFindGrabbable (4260–436a) scans source dot order using an inclusive ±6-pixel box for this path; DOCanGrab (4464–44fe) tests the first found dot's nonhuman permission byte+0x10. It does not seek a later permitted match after that first match is denied.

On acquisition the PU moves to current raw dot pixel plus kind rider offsets [(-9,0),(-9,0),(-1,-8),(-11,-8)], selects start=8+11×kind through start+11, writes start immediately and clears deadline. Eleven later callbacks reach the final frame, hide the puddle, detach its clock and invoke DPCreate. PUPositionRiders (8658–86b8) adjusts acquired puddles when dots move; dynamic dots remain outside this helper's supported scope.

DPCreate (CODE7:0b14–0c6e) has a32-slot lifetime allocation limit until reset, including hidden droplets. It starts on the acquired dot at its raw sprite pixel, frame0, prefers the vertical axis, attaches scalable50 with current-count snapshot, sets move deadline+adjust150 and clone deadline+adjust700, and calls DPGrabbed immediately. DPGrabbed (0638–06ee) checks human DOCanGrab permission. A denied dot creates a fader and hides/detaches the droplet. An allowed dot occupied by the human causes RODied reason10 unless that human is sliding. There is no ordinary-enemy protected-dot exemption in this branch.

DPWandGrabbed (04f4–055e), called at the beginning of DOGrabbed (CODE6:4600–461a), updates the cached human pivot. Any visible DP on that dot with absolute sprite frame0 causes reason10 death. This hook has no sliding check. Call it on initial human attachment and every successful human grab, including a transfer, before subsequent dot pickup effects. Same-pivot DP death is not general hand-outline overlap. The ordinary human-enemy outline rule must not substitute for these hooks.

DPCalcDir (CODE7:0278–04da) targets the cached human pivot's current pixel. It preserves vertical preference until Y matches, then horizontal until X matches; coincident positions choose positiveY. Direction bases are up26, down0, left78 and right52. If both axes differ and latchedTick is strictly greater than cloneDeadline, it synchronously creates a droplet on the same dot, runs its initial DPGrabbed, sets opposite preference, calculates its direction and sets its moveDeadline=1. The parent resets cloneDeadline even if the32-slot limit prevents a clone. Multiplayer target selection is source-visible but deliberately unsupported here.

DPFrameProc (0766–0aca) waits without animation while moveDeadline is nonzero and now<=deadline. On expiry it calculates direction/cloning, sets raw base to current-dot pixel minus48 on a negative travel axis, selects base..base+18, records previousDot, clears currentDot and deadline, then advances once in the same callback. Only relative phases4..8 and19..25 test dot outlines. DOCheckCollisions (CODE6:4d0a–4d56) scans all88 source dot slots in order and returns the first qualifying sprite-outline collision; the DP subsequently ignores that result if it is previousDot. Do not pre-filter previousDot from enumeration. The dot must have a sprite and either its flag+0x12 or sprite visibility must be true. This is distinct from acquisition permission.

If phase9 is reached without a dot collision, the DP enters extension range19..25. Each entry/wrap to19 moves its raw base another48 pixels along the same axis. A collision during an eligible phase selects the encountered dot, restores range0..18 relative to direction base, jumps to phase9, sets raw base to destination-dot pixel minus48 on a positive axis, and requests sound9. Ten further callbacks reach wrapped phase0, call DPGrabbed, set move deadline+adjust150 and return to absolute frame0 at the dot. Thus missing neighbors are crossed by animation and outline checks; graph adjacency alone does not model pursuit. During active collision phases, raw sprite base outside inclusive SU universe clipping bounds hides/detaches the droplet. The caller must supply the source universe bounds; no invented board-edge test is embedded.

## Clocks, reset and uncertainty

PU uses scalable100, DP scalable50 and DP faders unscaled100 (CODE6:8002–8010; CODE7:00aa–00c8). With scalable base50 adjusted at difficulty60 and secondary100, the base period is83 MT units. Client divisors are respectively2 and1. Under normalized60 guest ticks/second and16 MT units/tick, sustained counts are about5.783 and11.566 per second. Unscaled100 derives from unscaled base50/divisor2, about9.6 counts/second. These are calculated source rates, not measured native rates. A sprite runs once when its client count differs, without catch-up for all skipped changes. Shared clocks persist across actor resets.

MTAdjustPeriod (CODE7:3656–36ae) performs two integer stages: trunc(trunc(period×100/difficultyRate)×100/secondaryRate). **PU/DP deadlines add that result to Macintosh guest ticks, not MT16-unit counts.** At60/100, adjust150=250 ticks and adjust700=1166 ticks, approximately4.167 and19.433 seconds at normalized60 guest ticks/second. PU samples TickCount directly; DP and frame callbacks use A5−0x12a0 latched by CODE1:68c6–68cc or7f6c–7f72 before sprite processing. Strict `>` comparisons and callback sampling add delay. The helper requires caller-supplied adjusted delays and imposes a bounded nonwrapping tick range; it does not assume host milliseconds or claim original hardware pacing.

PUReset (CODE6:81ba–820a) restores every instantiated puddle to its dormant start. DPReset (CODE7:0108–0172) removes/frees every tracked DP sprite and clears the allocation count. ROReset runs subsystem reset callbacks, then CODE7:3dfe calls SUDisposeOneShots (CODE4:49fe–4a4c), removing the automatic faders as well. DP faders use frames104..106, current count snapshot, unscaled100, direction+1 and automatic disposal on range overflow; SUAutoFrame marks disposal after the next callback beyond106 (CODE4:3de2–3e4a). Integrate this with the established normal single-player death freeze and15-particle barrier, not an immediate local PU reset. Reinitialize cached human pivots through initial-grab notifications. Underlying clock state remains external.

## Helper and integration contract

`prototypes/clockwerx-html5/oil.mjs` is a generic, source-only set of immutable state primitives. Its12 synthetic tests cover filtering/capacity, both board origins, strict deadlines, skipped-count behavior, all four PU approaches, pursuit axis switches, the two death hooks, gap extension, previous-dot suppression, strict clone conditions, synchronous clone dispatch, sparse outlines and unsupported gates. Tests passed with `node --test prototypes/clockwerx-html5/oil.test.mjs`. They do not qualify an actual level or runtime.

The caller must supply original dot outlines/permissions/raw positions and clipping bounds, observe the shared source clocks, call the human grab hook before dot effects, execute clone creation synchronously, preserve source sprite traversal order, enforce32 allocations, dispatch sound/death events and remove all transient actors/faders at round reset. Freeze means suppressing callbacks while clocks continue according to the surrounding source model. `advanceDroplet` represents one callback; it does not observe clock counts itself. `observePuddle` does observe its own saved client reference. The follow-up [integration source supplement](oil-integration-source.md) resolves static-dot adapters, clipping and linked-list order, and adds the optional synchronous `onClone` hook. That supplement supersedes the initial traversal uncertainty here; runtime integration still needs validation.

Keep Oil inactive until source traversal, source dot collision, death/reset integration, native timing and native visuals pass independently. `oilUnsupportedReasons` makes these gates explicit. Reject multiplayer, dynamic dots, hyper dots, other dot programs and bomb/orphan interactions. The source includes those branches, but these helpers intentionally do not pretend to implement them. Current code uses bounded nonwrapping ticks and static dots; later campaign resources need fresh qualification.
