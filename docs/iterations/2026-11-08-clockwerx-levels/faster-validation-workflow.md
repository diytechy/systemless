## Evidence tiers

**Search trials:** keep exact immutable source/profile/input identities, aggregate constructor/reset/update/RNG accounting, compressed legal input runs, per-update player/NPC canonical frames and physical centers, relevant mover/program/mark/bonus state changes, semantic events, original collision outcomes and terminal snapshots. Every failure remains indexed. Use periodic complete checkpoints and a bounded detailed pre-failure window. Do not write a complete growing game snapshot before and after every collider in every failed trial.

**Chosen witness:** replay all inputs from fresh construction with original collisions and RNG provenance. Retain complete state and consumed query/hook/collider ordering using either the old full format or a reviewed lossless compact format. Run a fresh literal proof and compare complete reconstructed state/semantic lineages. Administrative metadata differences stay explicit; do not normalize away state differences.

**Original and visible comparison:** retain per-level original access/goal evidence and a visible SVG goal. Use the independently frozen original-only fitter when needed, preserving ambiguous observations and timing residuals. For known mechanics without a discrepancy, avoid exhaustive diagnostic matrices and multiple nearby/reset experiments by default; label any untested reset/margin/phase scope explicitly. Escalate on new mechanics or a concrete mismatch. Do not accept a scene from source inspection or solver success alone.

## Before using a new observer

Use a small, fixed accepted literal and identical immutable engine/fixture/settings to compare the old and compact observers. Bound constructors, updates and wall time before execution. Verify matching inputs, per-update source state, events, collision outcomes, RNG and final state. Instrument simulation, snapshot construction, serialization/output and hashing separately. Keep both failed and successful observer checks. A short check validates its exercised paths, not arbitrary observer passivity.

For detailed lossless records, store immutable inventories once by hash, then exact state deltas/checkpoints and compact call/return rows; validate reconstruction against the old representation. Batch writes under a bounded memory limit and retain crash-safe counters. Do not remove original collision calls, mutate clocks/state, inject a favorable RNG seed or sample away a material discrepancy.

## Coordination and reuse

- One reusable harness accepts decoded level, semantic capability recipe, profiles, cold selection and input policy/literal. Keep owned inputs outside Git. Add timers/summary receipts once rather than rebuilding harnesses for each level.
- Give a worker a complete bounded work package: prepare, execute within its stated limits, save failures, verify and return a result. Root reviews the result and changes involving new source behavior or external/live mutation. Routine reversible preparation does not need a separate approval conversation.
- When engine bytes change, run focused public tests and representative affected full-route regressions. On unchanged frozen bytes, reuse that qualification; do not rerun all prior levels for each new map.
- Two or more authorized workers may prepare/test known-mechanic levels on immutable source snapshots. New mechanic integration is serial. Native emulators, conversions, original-only fits, benchmarks and heavy builds stay sequential; no duplicate owner or automatic timeout retry.
- Keep one short operative handoff plus machine-readable queue/receipts. Read historical multiGB traces only to answer a specific question not already answered by a compact audit. Preserve them, but do not continually copy or rehash them for status checks.
