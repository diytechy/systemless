# Bomb runtime source implementation review

`bomb-runtime.mjs` and its tests are new, unlinked source-only preparation for Child Bombs, catalog 10 / resource 10963. They do not activate a scene or alter SourceRound, StaticDotRuntime, the level loader, app, package files, earlier helpers or assets. **28 focused tests pass: 20 new and 8 existing.** Native/browser gameplay, rendering, audio and level acceptance remain outstanding.

The private source-data probe independently matches the actual raw binary to decoded and queue SHA256. Its eight BO records and two active GO records construct successfully with the original injected fuse routes. After the ignition deadline is made eligible, the probe reaches the terminal with 339 changed-count callbacks: five ignition callbacks and 334 travel callbacks. Ten explosion callbacks then hide it. This is a source-data adapter check, not a measured native duration, route or safe player approach.

## Integration interface

Construct `BombRuntime({bombs, goodies, routes, mode:'Child', unsupported:[], scope}, adapters)`. Supply the normalized mode-filtered inventory as `scope` (or call `assertBombRuntimeScope` before wiring): it checks dot/actor restrictions and rejects active PU/DR/DS/EL/GN/TR/HY/EX or unknown future sections. Inactive masked records must contribute zero. Primitive-only tests can omit scope, but a board integration must supply this validated inventory. BO records may be raw version-6+ four-word records or normalized row/column/kind/flags/padding. GO records must already be Child filtered and provide row/column/initialFrame. Private route objects provide kind, signed Point word pairs, entry/exit tokens, terminal flag and three transform flags. No original map, route samples or program strings are embedded in source/tests.

Adapters are required for `clock(name)`, `latchedTick()`, `freshTick()`, `adjustPeriod(n)`, `gridPixel(grid, offset)`, `effect(event)` and `collides(kind, sprite, actor)`. Source mutation/collision adapters must be synchronous; asynchronous functions and returned promises are rejected. `gridPixel` must implement the source RO coordinate contract, not add an already-centered dot anchor a second time. `BOMB_CLOCKS` and `BOMB_SPRITES` disclose periods, scaling, groups, logical layers and raw grid offsets.

Call `observeMatch`, `observeSpark`, `observeExplosion` or `observeGoodie` at that individual sprite's actual place in live SU traversal. Do not advance whole pools as snapshots. The caller owns source physical layer mapping, insertion ordering, cached successor semantics and persistent MT clients. LI and SR use logical layer 3; explosions layer 2; GO layer 15. `append-sprite` is emitted only on first pool insertion. Reuse snapshots the current client count, suppressing a same-count callback even if newly appended sprites are visited during the current sweep.

Call `checkGoodie`, `checkMatch` and `checkSpark` separately in the existing actor collision pipeline. Human source order includes spike, goodie, puddle, match, spark, starburst, wall and door; the module does not collapse those stages into a single invented collision function. A death latch alone must not skip subsequent effects from that source callback. `freeze(true)` is for the completed source barrier; the current explosion callback still completes if a handler requests freezing. Thaw coalesces changed counts once.

`effect(event)` dispatches immediately. Returned event arrays are diagnostics and must not be dispatched again. Explosion `stationary` and `moving` stages invoke the caller's object-specific tests/destruction. Use `descriptorFrame`, the old committed image, for outline collision; `callbackFrame` is the next animation frame. Stationary SP/WL handling uses source topology/grid predicates, not a generic flame radius. DS/EL/GN/TR/DP stages remain in order even when absent; their active combinations are gated, not silently implemented.

## Clocks, ignition and capacities

The source clients are unscaled 100 for LI, scaled 62 for SR, unscaled 150 for explosions and unscaled 200 for GO. These are MT source periods, not milliseconds or guessed wall-time seconds. SU observes count inequality and invokes one callback; missed counts do not cause catch-up. LI/GO animate one frame even while hidden if their sprite is traversed. Dynamic spark/explosion activation snapshots its current count. The caller must retain these clocks through resets/freezes instead of starting fresh timers on input.

BO limits are 60 records and 5 LI matches. Armed humans may ignite any match; ordinary nonhumans additionally require a nonzero flags byte. Spark allocation runs before all same-grid LI are hidden, sound 11 is requested and the match is disarmed. A full 17-slot SR pool still consumes the match. Flags are not difficulty masks, and the code tests any nonzero flags, not only bit 0x20.

A spark starts at frame 0 in range 0..3. Its deadline is latched guest tick plus `adjustPeriod(60)`; waiting tests a fresh tick strictly greater than the deadline. It then selects frame/range 4..8. Reaching 8 changes range to 8..11 and marks travelling; that callback does not move a path point. Later callbacks erase the old source patch and advance one path index. The erase adapter receives old raw base and descriptor frame; it must use the original current descriptor rectangle for the 6×6 background copy, rather than treating raw base as a visible top-left corner.

Route direction is positive only when the supplied token equals the route's entry token; otherwise it starts at the last sample and travels backwards. Leaving a fuse increments the serialized BO index and passes the selected forward/reverse exit token. It never searches geometrically for a nearby fuse. Vertical reflection, horizontal reflection and swap precede translation by ROGetPixel(grid,+6,+6). Constructor checks require each starter to reach a terminal and reject unsafe terminal +1 blast neighborhoods; source route hashes and endpoint geometry continuity remain caller checks.

A terminal requests sound 12 before first-invisible allocation among six explosion slots. Exhaustion drops the explosion after sound, then the spark still hides/detaches. The source performs an additional SRPosition call after hiding with an out-of-path sample; the helper deliberately omits this unobservable private-memory read. It is not a supported malformed-route behavior.

## Explosion and actor effects

At callback frame 3, stationary order is SP, DS, EL, GN, TR, WL, DO, followed by moving DO, DP, WA. At every callback frame 3..10, moving order remains DO, DP, WA. Frame 4 then paints group 1400 crater frame 14 and repeats stationary DO. WLAnnihilateSprites is source-empty. Frame 10 performs moving effects before hiding/detaching; image index 10 is a callback sentinel and commits as descriptor 9. Frame 3 collision therefore uses descriptor 2. There is no radial BO-to-BO ignition path here.

`bombActors` checks live visible actors in unique ascending source-slot order, using a synchronous caller-provided original-outline test. Each hit is hidden and receives Child hidden-until metadata equal to latched tick +300. Human slots 0/1 invoke reason -1; scanning continues after this death callback. Ordinary types 1–3 remain hidden until WA reset. Source WAEnemyOneFrame auto-resurrection checks saved type 5 specifically, so a timestamp on an ordinary enemy is not permission to revive it. Rotating spikes and busters are rejected by this bounded actor adapter. Travelling visible sparks cause human reason 15; ordinary enemies do not run that spark-death query and spark hits do not consume the spark.

The earlier Bombs report called CODE6:8a34 an Oil droplet wall-shatter path. That address belongs to PR projectile processing; this attribution must not be used to add an Oil-only or blast wall-shatter rule. The Child explosion stage here calls WLBombed's grid/topology removal. Actual DP, projectile and weapon integrations remain separate.

## Burnt dots and exact special-dot hook contract

`applyBombDotHit` and `bombStationaryDots` preserve pivots, goals, colors and both grab permissions. Stationary order is (r,c), (r+1,c), (r,c+1), (r+1,c+1). Human-unavailable dots are skipped. Available ordinary dots gain transient burnt look 0x40; rings prevent that bit from being added. Bonus state clears when present. Burnt ordinary main art uses 92+color, with original secondary descriptor and RAW anchors supplied by the caller.

The required `sourceInBackground` field means **DOInfo +0x12**, as established by DOOptimize (3cca onward), not the current runtime's generic `sourceCollidable` field. Source optimization excludes look mask 0x0b94, including ring, checkpoint and bonus looks. A background dot is repainted on each bomb call even if state did not change, which restores it over the frame-4 crater. An unoptimized live sprite updates look only when state changed. The callback reports `paintBackground`, `updateSpriteRange`, `minimum` and `maximum`; a range update sets both main/secondary current frames to minimum but must not reset unrelated clocks, step, permissions or overlay state.

For the pure available rings in Bombs, ring look 0x200 prevents adding burnt look. Their min/max remains 23+7*color through min+7. An ordinary bomb hit with no bonus makes no live-sprite look update. If a ring bonus is removed, DOUpdateLook recomputes that same range and resets current frames to minimum. Human DOReleased still tests the ring bit, clears human availability, advances both current frames, attaches the ring timer and orphans other occupants. A collapsed/growing human-unavailable ring is skipped by the blast. Thus the existing pure-ring range need not become 92+color. Combined ring/checkpoint/slowdown states must not be inferred from this result.

Checkpoint main look 0x100 has higher priority than burnt look in DOGetLook (2c88–2ce8), retaining range 79..89. A first bomb hit can nevertheless add burnt metadata and call DOUpdateLook, setting the current frame to 79 while preserving existing step/client state. Protection raw 0x40 instead maps to DOSpec+0xb / DOInfo+0x1f and a separate miscellaneous type-2 overlay. It is **not** main look 0x80; that look is slowdown. A protected ordinary base may become burnt without clearing its protection flag or overlay. Protection does not prevent WABombed's direct hit/death path.

DOReset (2220–230c) first clears burnt bit 0x40 and calls DOUpdateLook if a main sprite exists; it then restores original bonus and calls DOUpdateLook, resurrects rings, stops/detaches static checkpoint animation, handles slowdown/moving/up/down state and clears the selected checkpoint pointer. Consequently a burnt checkpoint resets to frame 79 through the earlier burn-clearing look update. An unburnt nonbonus checkpoint can retain its current frame through ordinary round reset. DORestartLevel (4be6–4c30) explicitly resets the selected checkpoint's main/secondary frames to 79 before detaching/clearing selection. A future parameterized look update must run before StaticDotRuntime's ordinary checkpoint reset branch; calling a generic ring/checkpoint reset on every appearance change would alter source timing.

These checkpoint/protection/combined details are a precise source contract for review, not newly supported combinations. The new dot helper rejects protection, checkpoint, slowdown, transfer-death, moving/up/down and connector combinations. No existing ring/checkpoint/protection helper was edited.

## Goodies and reset ownership

GO initial-frame requests outside 0..16 retain clone default 0; the actual requests 59 are not modulo-reduced. Human collection order is sound 22, flourish creation, floating 1000 score, collected latch, +10 time, +1000 bonus for the source actor slot. Flourish uses RO offset (+18,+18); floating score uses x+10/y+16, after source Point subtraction of vertical 2 and horizontal 8. Visibility persists until the flourish's completion callback. First visible collision wins even if that goodie is already latched, temporarily blocking later overlapped goodies. Child nonhumans cannot collect through this adapter. There is no carried-match inventory and no new goal requirement.

`BombRuntime.reset()` rearms matches, shows LI/GO, clears GO collection, hides/detaches SR and explosions, and invalidates stale flourish completions. It retains LI/GO animation phase/reference and pool insertion identity. The caller must restore DO look/bonus/permissions/rings, SP visibility, WL topology/background, WA visibility/program/timing and score/checkpoint state through their own source reset branches. That external restoration is intentionally not hidden inside this module. A level reconstruction uses a new instance.

## Validation and remaining gates

The 20 new tests cover malformed scope/capacities, synchronous adapters, permission and consumption order, strict ignition deadlines, coalescing, reversed serialized transitions, path transforms, pool exhaustion/reuse, old-descriptor blast order, crater redraw, continued effects after death, burnt-ring preservation, actor slot/death behavior, spark eligibility, GO latch/deferred hide/overlap, hidden animation and freeze/reset. Existing eight helper tests remain passing. Test paths and boards are invented small fixtures, not original content.

Original source paths/profiles, source excerpts and the actual-data probe remain private under the bombs evidence directory. The companion JSON records source offsets, hashes, limits and probe results. No native/emulator/browser/build/benchmark/conversion ran, and no root runtime, existing helper, asset, queue, media or save was changed. No commit, upload or deployment occurred.

Root reports the accepted Some Dots V2 baseline now has **55 payloads**. Future Bombs QA must preserve every accepted byte and copy only the **nine Bomb-owned additions**. The older Bomb candidate contains Some Dots V1 files that must never overwrite accepted V2 SVGs. This preparation did not touch either asset set.

Native geometry/clock phase, original outline integration, exact live callback traversal, wall/spike topology adapters, score/time/UI integration, source reset visuals and a survivable input-only goal route remain required. Level 10 is unaccepted. All new files and source-only workloads are released.
